# v3.0.0 — Serval

Working checklist for the rename release. One box per change. Coordinate across chats
here: claim a slice by writing `in progress (YYYY-MM-DD)` on the first item you take, check
the box when it is on `master`.

Parent: [TODO.md](TODO.md) (`v3.0.0 — Serval`). Stamp the version only when this file is
all `[x]` (or explicitly deferred below).

**Rule:** nothing that publishes the new name (ghcr, README install instructions, social
preview, landing page) ships before the rename is in the binary. The Nyaa descriptor
travels in the same major so the user goes through **one** migration.

**IDs are stable.** Refer to them in chat (`taking R3–R5`, `N1 is done`). Do not renumber.

---

## How to use this file

1. Lock **Open decisions** before any rename diff. A chat that invents a binary name or a
   data-dir folder forks the release.
2. Take a **contiguous slice** (e.g. `N1–N2`, `R10–R16`). Specs (`S*`) before the work they
   gate.
3. Each slice still follows the repo rules: `go test ./...`, update `docs/agents/` when
   the slice changes endpoints / config / env / files / patterns, CLI parity when the
   slice adds an API action, English in every file you touch.
4. Windows installer / service is **v3.1.0**. Do not pull it in.
